## 1. Look-ahead — clean

Command: `git diff exp/r037 exp/r044 -- src/features.py src/model.py`

One new sales-derived column, `roll_mean_3`, built in `asof_features` (branch features.py
lines 105-108) by adding `SHORT_ROLL_WINDOWS = (3,)` to the rolling loop:
```
for w in (*ROLL_WINDOWS, *SHORT_ROLL_WINDOWS):
    lo, hi = origin_pos - w, origin_pos
    out[f"roll_mean_{w}"] = panel.values[:, lo:hi].mean(axis=1)
```
For w=3 the slice is columns `origin_pos-3, origin_pos-2, origin_pos-1` (hi is exclusive), all
strictly less than `origin_pos`, where `origin_pos = panel.pos(origin)` and `origin` is the first
forecast date (contract, features.py lines 5-6). `origin_pos >= MIN_HISTORY = 28` is enforced, so
`lo` is never negative. The value is computed once at the origin and repeated across the 28
horizon rows (`build_frame` line 138), so it is constant over the horizon. Training rows come from
`training_origins()`, whose newest origin is `fold_origin - 28` with the assertion
`candidate + 27 < fold_origin`, so no training row's feature or target reaches the fold origin.

Consumer: `LGBMXmasRoll3.FEATURES = [*LGBMChristmasZero.FEATURES, "roll_mean_3"]`. Not added to
`FEATURE_COLUMNS`, so `lgbm_baseline` and `lgbm_xmas0` are unchanged (their config hashes
900159c6f3dd and b759aafd2f04 reproduce, see item 8 here and in the r037 review). The `christmas`
post-processing is inherited from r037 and audited there.

every seed, which is the strongest fact in the branch's favour. INCONCLUSIVE, not FAIL.
