## 1. Look-ahead — clean

Command: `git diff main exp/r060 -- src/features.py src/model.py` (features.py +62, model.py +26).
`build_frame` and `asof_features` are unchanged. Nothing new goes into the model. The change is a
post-fit multiplier, `LGBMXmasThanksgivingDept.postprocess` = Christmas-zeroed prediction x
`event_window_multipliers(panel, panel.pos(origin), 28, "Thanksgiving", "dept_id")`.

Index arithmetic in `event_window_multipliers`:
- `ev = event_positions(panel, "Thanksgiving")`: `exog_dates.get_indexer` of every calendar date
  whose text columns equal "Thanksgiving". `Panel.__init__` raises unless `exog_dates` starts on
  the panel's first day and is daily-contiguous, so an exog index is the same date's panel column.
  Calendar events are published in advance.
- Target day: `h = t + k - origin_pos` for k in 0..3, written only when `0 <= h < 28`.
- Values read: `totals[:, src]` with `src = tp + k`, skipped unless `src < origin_pos`, and
  `totals[:, base]` with `base = src - 7j` for j = 1..4, all `< src < origin_pos`, and
  `base[-1] = src - 28 >= 0`. The skip condition is the `if`, not the assert. Both hold on the
  index expressions themselves.
- `group_totals` sums `panel.values` over the whole snapshot and caches it on the panel, but the
  only columns read are the ones above.

For fold 1 (origin 2015-11-23) this means 2015-11-26..29 (h = 3..6) get ratios from Thanksgiving
2011-2014 and their k = 0..3 days, all before 2015-11-23. No other fold window contains a
Thanksgiving. Row order: `build_frame` builds `id` as `np.repeat(ids, horizon)` (series-major), the
left merge on `date` keeps left order, and `out.reshape(-1)` on (n_series, horizon) is also
series-major, so the multiplier lines up with the prediction rows.
